## Risk register

| Risk | Likelihood / impact | Mitigation | Owner | Status |
|---|---|---|---|---|
| Requirements change late in the semester | Medium / High | Confirm acceptance criteria with guide; manage scope through backlog | Student + Guide | Open until reviewed |
| Integration issues between UI, API and DB | Medium / High | Integrate each sprint; maintain automated tests and repeatable local setup | Student | Monitor |
| Test environment unavailable | Medium / Medium | Document environment variables and DB setup; verify CI test environment | Student | Monitor |
| Insufficient proof for manual acceptance | Medium / High | Schedule testing, collect screenshots/logs and write actual results at each sprint | Student | Monitor |
| Final report or Scrum Book incomplete | Medium / High | Update dated records continuously and use submission checklist | Student | Monitor |
| Production secrets accidentally committed | Low / High | Use example env files, .gitignore and protected deployment secrets | Student | Monitor |

## Definition of Done
A backlog item is done only when its acceptance criteria are met, code is committed, relevant tests are executed and recorded, integration/build checks pass or failures are documented, related documentation/evidence is updated, and guide feedback is recorded at review where applicable.
