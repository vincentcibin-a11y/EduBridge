# Product Backlog — NetPulse

The detailed proposal backlog, with 16 user stories and testable acceptance criteria, is maintained in [NETWORK_MONITORING_PRODUCT_BACKLOG.md](NETWORK_MONITORING_PRODUCT_BACKLOG.md).

Prioritise and refine the backlog with the Project Guide/Product Owner and the network stakeholder. Proposed core epics are:
1. Identity and role-based access.
2. Approved network asset inventory and target policy.
3. Manual reachability checks and safe timeouts.
4. Bounded scheduled checks and check history.
5. Dashboard metrics and response-time trends.
6. Incident lifecycle and alerts.
7. CSV reporting and audit records.
8. Automated verification, documentation and deployment.

**Status:** Proposed. No NetPulse application feature should be marked complete until it is implemented, tested, demonstrated and supported by evidence.
